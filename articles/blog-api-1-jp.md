## 【研究報告】Note & Qiita 同時投稿 API 連携の完全攻略ガイド

自作スクリプトによるマルチプラットフォーム投稿、無事に成功しました！ブラウザの Network タブを解析し、実地検証で判明した「非公式 API の真実」をここに記録します。

> **※注意**：本記事は非公式 API の利用を推奨するものではありません。サーバーへの負荷を考慮し、実行時は time.Sleep( 30 * time.Minute) などを挟むなど、紳士的な実装を心がけています。主な用途は、深夜の Cron による推敲した記事の同期の自動化を考えています。

## 1. Note API：一筋縄ではいかない「スパルタ」仕様

### ハッシュタグ（Hashtags）の厳格さ

- **全損リスクに注意**: 存在しないタグや不正な形式を一つでも含めると、**既存のタグまで全て消去される**というストイックな挙動を見せます。タグのバリデーションは必須です。

### ヘッダー画像 API

- こちらは予想に反して、Post 一発でスマートに解決できました。

### YouTube & コードブロックの「完全再現」

- **空タグは即削除**: <figure></figure> のように中身が空だと、note 側で「無効なタグ」として即座に消し去られます。
- **解決策**: UI が生成する <span>, div, iframe が入り混じった重層構造を、そのままリクエストに載せて送り届けるのが一番確実です。

### 追記

- NoteはどうやらSVG形式の画像をサポートしていないようだ

### Microsoft Edge について（情報募集中）

- だれか Edge の SQLite　データベース からいろいろ抜き出す方法知ってる方はいますか？
- 現状かなり時間がかかりそうなので、現在は **Firefox および Chromium** から情報を抜き出して対応しています。

## 2. Qiita API：最適化戦略

- **画像インジェクション**: Qiita には直接画像を上げる API は存在しないため、**「先に Note に上げた URL を Markdown の冒頭に差し込む」**か、**ファイルストレージ(Minio)**を活用しましょう。
- **YouTube 変換**: Note 用の figure 構造は動かないため、標準的な iframe 形式へ置換して送信します。

## 3. 開発における「唯一の正解」

- **SSOT**: 独自の **YAML ＋ Markdown** を正本として管理。
- **Network タブこそが仕様書**: 公式の Swagger などが見当たらない以上、ブラウザの UI が成功した際の JSON 通信こそが、我々にとっての「絶対的な正解」です。
